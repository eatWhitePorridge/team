# Team Console

React 19 + TypeScript + Ant Design 的 Team / 账号管理界面，Flask 提供 API，SQLite 提供独立的脱敏读索引。

## 当前边界

**默认使用独立的空白数据目录 `team-console/data/store`，不加载历史数据。** 账号、批次、母号、任务、凭据、Cookie 和日志均保存到该目录；不会复制、删除或修改旧项目的历史记录。后续重启会保留在新系统中导入的数据，不会每次清空。

授权、额度、邀请、切席和移除仍复用主项目的业务代码，在新后台进程启动时将存储路径绑定到独立目录。不要把本文件夹单独复制出去就当成代码依赖也已独立的完整系统；业务主存储仍采用原有 JSON / SQLite 格式，尚未全面改写为 SQLite 主库。

- 启动新后台只注册母号路由，不调用旧系统任务恢复、不将旧任务改为中断、不恢复旧调度。
- 索引直接只读读取账号 / 批次 JSON 及有效的 progress journal，不调用会触发恢复写入的旧 `_load_accounts()` / `_load_batches()`。
- 必须以独立进程运行新后台，不要嵌入正在运行的旧 Flask 进程。新旧后台默认数据目录不同，可以分别运行；不要将多个进程手动指向同一数据目录并发写入。
- 旧的 `team-console/data/read-model.sqlite3` 历史读缓存不再使用，不会导入新目录。

## 本地运行

### 授权 403 与封禁状态（2026-10-04）

- 普通 / Team 授权均改用本地已采用的 Codex 专用参考画像（TLS chrome146、HTTP/JS Chrome 149、出口 GeoIP 语言时区），只作用于 Codex 入口；母号固定代理与管理请求不变。此配置是兼容性调整，不保证消除上游 CF 挑战。`CODEX_BROWSER_FAMILY=firefox` 可回退原配置，`chrome146` 可选原一致画像。
- `account_deactivated` / `account_deleted` / `account_banned` 是终止结果：内部 OAuth 恢复、Team 外层重试、批量队列与重新入队均不再自动重试。CF 挑战、普通 403、网络错误不因此被标为封禁。
- 账号列表在电脑和手机均显示红色「已封禁」，授权状态可筛选「已封禁」。封禁优先于旧 Token 的存在；保留旧凭据与历史套餐，不再将其显示为当前已授权。现有明确封禁记录会通过读索引自动更新，不需要重新授权。

在本目录的 `frontend` 下先构建：

```sh
npm ci
npm run build
```

在主项目根目录运行：

```sh
.venv/bin/python -m pip install -r team-console/requirements.txt
.venv/bin/python team-console/server.py
```

默认地址 `http://127.0.0.1:5050`。启动前复制本目录 `.env.example` 为 `.env`，填写登录密钥（必填），其他配置按需设置：

- `TEAM_CONSOLE_PORT`：端口，默认 5050。
- `TEAM_CONSOLE_HOST`：默认 127.0.0.1；对外监听必须配置访问密钥。
- `TEAM_CONSOLE_API_KEY`：API 访问密钥，进入界面时先在独立登录页输入并验证，通过后才加载管理菜单、账号和任务。所有 API（包含复用的母号接口）都受保护；未配置密钥时，登录验证接口拒绝登录。
- `TEAM_CONSOLE_DATA_DIR`：留空默认使用本目录 `data/store`。相对路径以 `team-console` 为基准；不自动迁移任何旧数据，也不能在已运行的进程中热切换目录。
- `TEAM_CONSOLE_AUTH_WORKERS`：普通 / Team 授权共享的实际执行槽位，默认 100，可设为 1–100。启动时固定，调整需要重启新后台；不沿用旧系统的 50 路限制。

前端开发：在 `frontend` 执行 `npm run dev`，默认 3050，API 转发至 5050。

登录密钥验证成功后保存到同源 `localStorage`，同一浏览器配置文件、同一协议 / 域名 / 端口的标签页共享登录；新标签页和刷新仍先向服务器验证，再加载后台。退出 / 密钥失效同步到其他已打开的标签页，迟到的旧请求不能覆盖新登录；旧 `sessionStorage` 密钥仅在再次验证通过后迁移。退出保留无密钥标记，防止旧标签页恢复已经退出的登录。存储不可用时退回当前标签页内存，不跨浏览器、设备或无痕窗口同步。上游母号自己的 401 不会退出管理台登录。密钥不会硬编码到前端源码或构建文件，也不会放入 URL。

## Docker 独立部署

部署目录结构（与旧后台完全分开）：

```text
/opt/team-console/
  compose.yaml          # 从 team-console/deploy/compose.yaml 复制
  source/               # 主项目业务代码 + team-console；不包含历史数据和 env
  business.env          # 现有代理/授权等业务配置的独立副本，只读挂载
  .console.env          # TEAM_CONSOLE_API_KEY，只读挂载；不要提交 Git
  data/                 # 首次为空，重建容器仍保留新数据
```

`data` 目录和两份 env 必须事先创建，属主设为 `10001:10001`，权限分别为 `700` / `600`。访问密钥可沿用旧后台授权码，但不要放进镜像、命令行参数或构建日志。容器启动时必须有非空访问密钥，否则拒绝对外服务。

```sh
cd /opt/team-console
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100 web
```

默认发布 5050 端口。镜像通过锁文件构建 React 前端，使用单进程 Uvicorn：SSE 由原生异步处理，普通 Flask API 经 a2wsgi 使用独立的 16 个 HTTP 线程；授权仍使用原来的独立 100 路线程池。长连接不占 HTTP/授权线程。普通 / Team 授权共享容量，不按每批串行等待；空出的线程立即领取下一个任务。不要扩成多个进程/副本共享此数据目录。

Compose 为新容器配置 4 CPU、4 GiB 内存、5 GiB 内存加交换空间总上限、2048 进程/线程上限；不会修改旧容器。任务中的 Node 子进程同样计入容器资源限制。100 是并行任务上限，不代表远端响应速度或成功率保证。

镜像构建上下文采用白名单，不包含 `.env`、账号、Token、Cookie、历史日志和旧索引。运行时非 root、只读根文件系统，仅 `/data` 和 `/tmp` 可写；含带鉴权的健康检查、资源上限和滚动容器日志。Docker 不会安装或启动浏览器。

更新时只替换 `source` 并重新构建启动；不要覆盖 `data` 或运行清空目录的命令。回滚可以通过 `TEAM_CONSOLE_IMAGE` 指向上一个已构建镜像，使用 `docker compose up -d --no-build`；业务数据仍保留。

静态资源的目录和文件在镜像中分别规范为 `0755` / `0644`，仅作用于 `frontend/dist`，不能放宽 env 或业务数据权限。构建会以实际服务用户 `10001` 运行 `static_assets.py`，检查入口及懒加载资源可读；健康检查同时验证静态文件、首页 HEAD 和鉴权后的后端索引，避免后端正常但首页 500 仍显示 healthy。

## Bento UI（2026-10-02）

- 已移除旧经典 / 工作台双主题，统一为 React + Ant Design + 原生 CSS Grid 的 Bento 管理台；未引入 Tailwind、动画库、远程字体或其他前端框架。
- 登录、导航、总览、账号、批次、母号、任务和网络设置统一改版。总览以 2×2 账号资产主卡、2×1 母号入口和 1×1 真实指标构成层级；数据页保持宽列表，母号导航、工作区、席位和成员列表是独立区域，不嵌套卡片。
- Zinc 浅底、白色卡片、炭黑主卡和青柠强调色；卡片 16px、控件 12px 圆角。手机单列、平板两列、桌面四列，移动端席位筛选收为带数量的选择器，成员 / 邀请虚拟滚动与账号分页保持原行为。
- 微动效仅在精细指针 / hover 设备且允许动效时启用，支持键盘焦点、跳至正文和 reduced-motion。所有总览数字来自现有只读接口；缺失数据保留“—”，不虚构增长、完成率或连接状态。
- 本次不改变接口、代理、任务调度、并发、重试或任何业务存储。权限门禁、批量选择、两种授权、导出 / 复制、批次合并 / 拆分 / 删除、切席与邀请的提交链路保持不变。
- 精简版移除重复页标题和账号 / 批次顶部统计卡，数量并入列表标题；任务数量并入状态筛选，保留任务内账号明细。拆分批次统一放在“更多”，删除、两种授权等入口保留；列表获得更多高度。
- 登录、总览、代理和授权 / 切席弹窗删除营销文案及实现原理说明；错误、缓存时效、操作结果和不可撤销确认仍保留。代理页合并为设置和当前配置两个区域，不重复展示说明。
- 校验命令：`npm run check:design`（静态 token / 断点 / 动效声明和纯色前景背景对比度）、`npm run test:logic`、`npm run build`。不进行浏览器操作或 UI 测试；静态通过不代表已验证渲染、触屏和运行时无障碍。

## 本轮稳定性 / 性能改进

- 手机端（小于 768px）使用抽屉导航，账号 / 批次 / 任务 / 总览使用分页记录流；跨页勾选、筛选和原操作共用同一份状态，桌面仍保留表格。成员和待邀请在手机上收为单列紧凑记录，仍按容器宽度虚拟滚动、无前端分页，官网查询仍为 100 条一页。
- 手机批量栏保留两种授权，额度 / 拆分 / 导出 / 删除等收进“更多”；详情和确认弹窗支持内部滚动，适配安全区，输入字号 16px、主要触控目标 44px。仅调整显示，不改变授权并发、邀请切席并发、429 重试、代理、SSE 或接口。按约束仅代码审查、纯数据逻辑测试与构建验证，未进行浏览器操作或 UI 测试。
- 正确挂载 Ant Design App Provider，业务提示与弹窗可获取上下文。
- 页面拆分并按需加载；列表请求可取消，旧请求不覆盖新筛选 / 母号 / 工作区的数据。
- 成员一次读取本地缓存筛选结果，通过虚拟滚动列表展示；官网成员同步仍按每页 100 人。支持标准 / Codex / 基础席位统计、Hold 独立列表、单个及批量切换 / 移除。切换工作区或筛选会清空选择，移除 / 切席需确认目标。
- 母号详情右上角支持删除母号（手机端为垃圾桶图标）。二次确认后只清除本系统母号凭据、工作区 / 成员 / 邀请缓存和母号任务记录，不删除账号列表、不操作远端 Team 成员。运行中 / 排队中的母号任务会阻止删除；提交固定的母号 ID 与邮箱，防止旧页面误删复用 ID 的其他母号。超时只刷新，不自动重试删除。
- 母号工作区顶部提供「查询账单」：复用 Web AT 的只读席位费用预览，显示 `renewal_date`，不提交增席或扣费。原值按返回的时区保存，前端统一以 `Asia/Shanghai` 转换一次并明确标注「北京时间 UTC+8」；支持带 Z / 偏移的 ISO 时间和 10 位秒 / 13 位毫秒时间戳，不跟随电脑时区。无时区、仅日期、非法日期不猜测补时区；原始值、查询时间和单独的权益到期时间收在「时间详情」，`expires_at` 不冒充账单日期，也不据续费日期判定账号已过期。查询失败保留上次结果，工作区同步不覆盖独立的账单预览缓存；仅点击查询才访问上游，不自动轮询、不占授权队列。
- 成员额度读取 `local_account`；账号 / 成员额度展示实际窗口剩余比例，按量套餐展示接口返回的 credits 点数余额。零余额保留为零，缺失数据不显示为“成功”或 100%；旧记录需重新查额度才会补存点数余额。
- 授权进度轮询与弹窗独立；切换菜单后仍能查看进行中的授权。
- 全局任务进度使用一条带鉴权的 SSE（`GET /api/jobs/events`），业务状态提交后通知集中读取器，约 150ms 合并一次更新；不是每个客户端反复读 JSON。首次/重连发送完整快照，其余发送有版本的行增量。密码、2FA、工作区、凭据交换等阶段在执行过程中主动报告；区分排队、执行、重试和结果确认，结束比例仍以编排器确认的真实终态计算。所有活跃任务都保留，不再被最近 100 条记录截断。
- SSE 每 15 秒心跳，失联/代理阻断时自动重连并临时回退 1–5 秒串行只读轮询；健康连接停用轮询。慢客户端只保留最新状态，发送超时主动断开，每进程最多 64 条进度连接；重连全量同步避免遗漏。密钥只放请求头，不放 URL；密钥失效停止连接。读状态失败会报告不可用，不伪装成正常进度；后台 30 秒低频核对遗漏事件/外部改动。普通写操作不因重连而重发。
- 任务中心按授权提交聚合：一次普通 / Team 授权仅显示一条任务，显示账号总数、执行 / 排队 / 重试和成功 / 失败数；同一账号重试仍留在该任务内。点击“查看账号”可按邮箱 / ID 搜索并筛选状态，查看每个账号的阶段、尝试次数、套餐和失败原因，不再将每个账号放在顶层列表。
- 右下角全局任务浮窗在切换菜单时保留，复用同一条 SSE；采用 Bento 主进度卡、执行池和轻量指标，任务列表是独立区域，不再叠加另一个详情弹窗。桌面采用 4 列 / 主卡 2×2，平板 2 列；手机合并重复指标到单列主卡，详情随窗口滚动。全局窗口可收起，桌面有任务时自动打开、手机默认收起；手动收起的偏好在当前标签页刷新后保留。
- 每条任务可展开 / 收起，最多同时展开一条：授权内直接搜索 / 筛选账号，查看阶段、尝试次数、套餐和失败原因；母号任务内直接查看进度、阶段和完整操作结果。只在展开授权时挂载原有只读详情逻辑；收起任务或窗口即停止该详情读取，不新增 SSE，不改变授权调度。所有活跃任务及最近 3 条终态任务保留，正在展开的旧结果额外保留到用户收起（服务端已清理的任务不恢复）。完成比例依据真实终态，失败 / 取消不冒充成功；断线提示数据可能滞后。
- 授权任务详情使用只读鉴权接口 `GET /api/jobs/authorization/<batch_id>`，读取该提交的全部保留明细，不受共享实时流最近 100 条终态记录的限制；密码、Token、Cookie 和 2FA 密钥不返回。打开明细后实时合并现有 SSE，保留已完成的账号，另以低频 / 完成变更读取补齐快照；关闭弹窗停止详情请求。普通 / Team 各保留最近 20 个已结束任务的列表入口，所有活跃任务不截断；受已有流水线历史清理影响的旧任务会明确提示缺失明细，不将缺失计为成功。此改动不新增任务、不修改授权调度、100 路并发或重试策略。
- 任务详情按来源和 ID 跟随最新数据；账号/成员大列表不跟随任务进度提频，菜单组件隔离进度刷新造成的无关重渲染。以上不改变授权执行、并发、工作区校验或重试次数。
- Team 授权失败或返回 Free 等非 Team 套餐时，最多自动重试 6 次（首次加重试共 7 次）；普通授权重试策略不变，成功或手动停止后不继续重试。
- 两种授权的 `network_preflight` / `ProxyError` 使用独立代理预检预算，默认最多 10 次（含首次），不占业务授权重试次数；代理没有改变时也不会误扣业务预算。达到预检上限单独结束，Team 外层不再重试放大；HTTP 403、密码 / 2FA / 工作区阶段失败仍遵循原业务策略，封禁与手动停止仍立即终止。不会改动母号固定代理绑定。
- 「Team 授权」先确认工作区：支持从已保存母号选择工作区，或直接填写工作区 ID（无需录入母号）。打开弹窗时固定所选账号；切换母号会清空工作区选择，手动模式不携带旧母号信息。仅查询本地工作区缓存，不自动触发母号同步、邀请或切席。
- 指定目标通过 `expected_workspace_id` 写入授权任务及重试记录；只选择该账号认证响应中存在的工作区，并核对新 Token 的工作区和 Team 套餐，不回退到其他工作区。任务详情显示目标 ID。普通授权和既有未指定目标的 API 客户端保持原行为；新接口显式提供空 / 非法目标时会拒绝，选母号模式还需核对工作区属于该母号缓存。
- 账号 / 任务页显示执行池的实际运行数、排队数；排队中的任务不算已运行。`GET /api/jobs` 的 `runtime` 返回这些无凭据计数，不扫描账号 JSON。独立服务不在每个任务启动时并发 reload 全部配置，避免覆盖代理设置或让线程池退回 50 路。
- 普通 / Team 授权在独立后台启用批量调度：按模式和目标工作区分组，每次最多 100 条一起创建内部任务并保存一次进度，然后连续提交到同一个线程池。100 条是存储合并大小，不是等待整组结束的执行屏障。351 条只做 4 次批量入队；等待中的任务在任一线程空出后立即开始。
- 每个入队块之间以及子任务结果提交后优先确认完成结果，一次读取所需账号 / 任务状态、合并保存已确认结果，再通知 SSE。完成计数不等待整轮逐个建任务结束；仍保留身份、工作区、Team 套餐与重试预算校验，不能把 Free 或旧凭据冒充 Team 成功。此加速只由独立后台显式启用，旧注册与母号调度链不变。
- 批次管理只查询账号导入批次，内部 OAuth 执行批次不混入列表。
- 账号管理勾选后可「拆分批次」：支持跨页、跨导入批次选择，将所选账号移动到一个新导入批次，其余账号及空源批次保留。凭据、授权、额度、Team 关系和内部任务不变；有运行中任务时整次拒绝。只写一次小进度 journal，不重写账号主 JSON；使用恢复记录和请求回执，避免超时手动重试重复拆分。成功后立即更新索引并查看新批次。
- 批次可跨页勾选合并，选择保留的目标 ID；账号和凭据不变。支持单个 / 批量删除批次，需明确确认级联删除其全部本地账号（含归档）、凭据和 Cookie，不操作远端成员。两类操作只接受导入批次；存在活跃授权（含重试间隙）或额度等任务时整次拒绝，避免部分批次被改动。每次调用一次批量存储，成功后在同一索引事务更新批次和账号归属 / 人数。
- 账号行右侧可单个删除，勾选后可批量「删除账号」，均需二次确认。只删除本系统保存的账号及关联凭据、Cookie，不注销远端账号、不移出 Team；授权（含等待重试）、额度查询等运行中账号会跳过并给出原因。批量删除一次保存，不逐个重写大 JSON，删除后立即移除列表索引。
- 账号支持按保存的授权套餐精确筛选 `free` / `self_serve_business_prolite`，可与批次 ID 同时筛选；未授权或套餐未知不归入 Free。查询使用 SQLite 索引，不逐条读取凭证。批次页的“查看账号”会自动带入批次筛选。
- 账号邮箱旁可单个复制，勾选后可批量「复制邮箱」（手机端在“更多”中）。支持跨页选择，一行一个邮箱并去重；切换筛选清空选择，不会混入其他批次。仅使用已选行的邮箱，不请求凭据、不改变导出状态；复制支持 HTTP 部署地址，失败不会误报成功。
- 选中账号后，“更多 → 导出 2FA 三段式 TXT”下载 `邮箱----ChatGPT密码----Base32密钥`，一次读取所选凭据，原样保留密码中的空格和分隔符，不误用邮箱密码。已导入但尚未验证的密钥可备份并单独提示；缺失/无效/正在绑定的记录报告失败。只有显式、鉴权的导出请求返回明文，列表和 SQLite 不存入凭据，不更改 2FA 或 Codex 导出状态。
- 入队返回真实数量，零入队不再显示成功；导入成功但授权失败会分开提示；导出保留失败明细，不再把全失败变成空文件下载。
- 除切席收到明确的 HTTP 429 外，不自动重试远端写操作。网络超时、5xx、响应不明不会重复提交，401/403 仍停止。界面刷新成员读取的是本地缓存，远端同步需要用户显式提交任务。

### 席位控制与网络代理

- 母号工作区增加「待接受邀请」页签：无前端分页、虚拟滚动展示全部筛选结果；支持邮箱 / 邀请 ID 搜索、席位筛选及全选。页面只读本地 SQLite 缓存，点击“同步邀请”才读取官网；官网 GET 每页请求 100 条，offset 按实际返回条数推进，完整分页成功才替换缓存。
- 待邀请切席使用独立的 `invite_switch` 任务，单条 / 批量均按邀请 ID 逐个 PATCH `/backend-api/accounts/{workspace_id}/invites/{invite_id}`，请求体仅含 `seat_type`，不使用成员 ID，不调用新建邀请 POST。执行前核对当前工作区的完整邀请列表，只处理 `status=2`，不存在 / 已失效的邀请跳过，相同席位不重复写；不回查、也不重新发起邀请。
- 邀请切席没有 200 条总量上限，默认 5 路并发，确认弹窗可设 1–20；空闲工作线程立即领取下一条，不等待整批完成，每个线程独立 HTTP 会话并复用已验证的代理与身份。正常路径不再间隔 10 秒；遇到 429 时同工作区整体遵守冷却，随后按 10 秒间隔降速并持续重试。已加入成员切席的串行策略不变。
- 邀请切席的完成数 / 执行数通过 SSE 发布，成功响应直接更新对应缓存席位，不回查、不重做已成功项。取消或其他错误会停止派发、结束冷却等待，并收齐在途请求结果后结束；超时、5xx、401/403 不自动重放。重启中断的在途邀请记为待确认，不自动重试；全量名单变更仍以手动同步为准。
- 母号成员页提供席位用量 / 可用 / 已购 / Hold 概览；Hold 是单独的保留记录，当前仅展示，不发送成员切换或移除操作。
- 只有工作区明确开放 `usage_based` 时，才能邀请或切换到 Codex 席位。
- 账号批量栏和批次行支持选择母号、工作区，按保存的授权成员 ID 预览并提交切席 / 移出；无邮箱也不依赖邮箱匹配。实际执行复用旧服务的身份检查、限速和“不自动回查”规则。
- 母号成员切席取消单次 200 人上限，账号 / 批次切席也不再设单次账号数上限；保留请求体大小、ID 校验、去重、目标工作区和席位能力校验。并非一次并行发送全部请求，同工作区仍依次切换、间隔至少 10 秒。
- 切席收到 429 时不再尝试 3 次就结束：优先遵守 `Retry-After`（秒数或 HTTP 日期），没有有效头时按 60 / 120 / 180 秒退避，之后维持 180 秒，直到成功、手动取消或其他错误。服务端要求更久则等待更久，不截短到 180 秒；0 秒也保留基本切席间隔。任务消息通过 SSE 显示等待与重试次数，等待期间可取消。只重试当前被限流成员，复用原操作标识，不回查、不重做已成功成员；邀请和移除的重试策略不变。
- 邀请成员按每次 POST 最多 100 个邮箱提交，200 人分两次请求，不是 100 路并发。保留已有去重、取消、429 停止及提交后不回查 / 不自动重发规则。
- 左侧「网络代理」可查看已有代理数量及脱敏示例，显式替换或清空 SOCKS / HTTP 代理池，并设置额度查询路由及专用代理。不会将已有密码回填至前端。
- 未修改时沿用 `business.env`；修改后将独立覆盖配置写入 `data/network-settings.json`（0600 权限）。新建会话即时生效，重建容器仍保留；已有会话保留原代理。不改旧系统配置或只读挂载的 env。

### 索引行为

列表和统计请求只查 SQLite；后台线程默认每 2 秒检查源文件签名。主 JSON 未变、仅 journal 变更时不重新解析主文件。索引仅更新变化的行，账号变化后的批次人数由 SQL 聚合，无需重写全部批次。

首次启动索引未就绪时显示提示；后续继续提供上次完整快照。源文件损坏、读取途中被替换或 journal 不匹配时不会发布半份数据，后台自动重新读取。仍需扫描已变化的主文件；旧服务自身的业务 JSON 写入成本不在本轮消除范围内。

`data/store/read-model.sqlite3` 是可重建的派生缓存，不是凭据主库。账号及批次使用字段白名单；读索引不存储原始 `flow_snapshot`、密码、TOTP、AT、RT 或 Cookie。新导入的凭据由同一独立目录内的业务存储管理，整个数据目录默认被 Git 忽略。

### API 变化

`POST /api/accounts/export-sub2api` 返回 JSON 报告（`data` 是供下载的 Sub2API 内容，另有 `failed` / `warnings` / 数量），全失败为 HTTP 422。授权 / 额度查询全部未入队为 HTTP 409，部分成功保留完整计数和明细。前端与后端需同时更新，然后手动重启新后台、刷新界面。

## 离线验证

在主项目根目录：

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$PWD/team-console" .venv/bin/python -m unittest discover -s team-console/tests -v
```

测试仅使用临时 JSON / SQLite 和模拟业务服务；包括真实旧母号存储的临时实例，验证启动新后台不改变已有 running 任务。不会接触真实账号、调用外部授权或启动应用服务。前端执行 TypeScript / Vite 静态构建，以及 Node 22.18+ 的纯逻辑测试（`npm --prefix team-console/frontend run test:logic`）；使用假时钟验证轮询、退避、取消和任务快照匹配，不加载 React、不操作浏览器、不执行 UI 测试。

并发回归通过真实 API、持久化编排器和授权线程池提交 120 个临时账号（两种授权各 60 个），只替换最外层 OAuth 网络传输：断言同时运行 100、排队 20；只释放其中 1 个就启动第 101 个，而不等待整批结束。进度推送开启时同样验证，120 条活跃任务不截断。同时验证配置 reload 不重建池，取消 / 异常不泄漏运行计数。该测试证明队列与执行槽位，不代替真实上游网络压测。

实时链路回归执行真实密码/2FA 函数（网络原语全部模拟），在两个授权模式的 2FA 步骤暂停：断言授权尚未结束时 SSE 已收到对应阶段且结束计数仍为 0。另验证超过 HTTP 线程数的 SSE 连接不阻塞普通 API，及断连、心跳、版本跳跃、鉴权、慢客户端回收。不会对真实账号发起授权。

大历史数据回归另构造超过 10 MB 的账号 / 批次 / 任务 / 流水线文件，提交 351 个临时账号，验证前 100 个真实工作线程进入模拟 OAuth、其余排队。只释放一个账号时，SSE 必须收到 `1/351`、其余 350 个未结束，且第 101 个立即补位；断言只有 4 次批量入队 / 主任务文件写入，而非 351 次。此测试不使用线上数据，也不是上游成功率测试。

## 母号查看子号

母号管理中选定工作区后，点击「查看子号」进入账号管理。列表按该工作区已同步的成员缓存匹配本地邮箱，排除所有者、管理员及归档账号；不依据旧授权套餐或批次猜测当前成员身份。无邮箱或未导入的成员不会自动变成本地账号。

未同步成员时需先同步。子号列表支持继续按批次、授权套餐等筛选，也可返回原母号/工作区或切回全部账号。读取只访问 SQLite 缓存及账号索引，不触发远端同步、授权或大 JSON 扫描。

### 母号固定代理

- 母号管理 → 设置代理，可填写一条 HTTP/SOCKS5 地址，或从当前代理池分配一条。
- 未配置的母号首次执行管理请求时自动绑定；GET 列表/详情不会触发分配。
- 绑定加密保存在母号 SQLite 中，与 AT/Session 分开；重启、刷新 AT 或更新全局代理池不会重新抽取。
- 工作区发现、成员/待邀请同步、邀请、切席、移除、账单查询及并发邀请请求均使用该绑定。失败不自动换线，也不回退直连；空代理池或绑定损坏会明确报错。
- 任务排队/执行中或母号请求未结束时不能换代理。手动修改带母号身份与绑定版本校验，避免旧页面覆盖新设置。
- 固定的是代理连接地址，供应商是否保持同一公网 IP 取决于代理套餐/会话参数；不影响子号两种授权或额度查询的独立代理设置。
- 进程内活动请求保护遵循系统现有单 WSGI 进程约束（`workers=1`），不可运行多进程副本共享业务目录。
