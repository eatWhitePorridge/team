# Team Console

React 19 + TypeScript + Ant Design 的 Team / 账号管理界面，Flask 提供 API，SQLite 提供独立的脱敏读索引。

## 当前边界

**默认使用独立的空白数据目录 `team-console/data/store`，不加载历史数据。** 账号、批次、母号、任务、凭据、Cookie 和日志均保存到该目录；不会复制、删除或修改旧项目的历史记录。后续重启会保留在新系统中导入的数据，不会每次清空。

授权、额度、邀请、切席和移除仍复用主项目的业务代码，在新后台进程启动时将存储路径绑定到独立目录。不要把本文件夹单独复制出去就当成代码依赖也已独立的完整系统；业务主存储仍采用原有 JSON / SQLite 格式，尚未全面改写为 SQLite 主库。

- 启动新后台只注册母号路由，不调用旧系统任务恢复、不将旧任务改为中断、不恢复旧调度。
- 索引直接只读读取账号 / 批次 JSON 及有效的 progress journal，不调用会触发恢复写入的旧 `_load_accounts()` / `_load_batches()`。
- 必须以独立进程运行新后台，不要嵌入正在运行的旧 Flask 进程。新旧后台默认数据目录不同，可以分别运行；不要将多个进程手动指向同一数据目录并发写入。
- 旧的 `team-console/data/read-model.sqlite3` 历史读缓存不再使用，不会导入新目录。

## 本地运行

在本目录的 `frontend` 下先构建：

```sh
npm ci
npm run build
```

在主项目根目录运行：

```sh
.venv/bin/python team-console/server.py
```

默认地址 `http://127.0.0.1:5050`。启动前复制本目录 `.env.example` 为 `.env`，填写登录密钥（必填），其他配置按需设置：

- `TEAM_CONSOLE_PORT`：端口，默认 5050。
- `TEAM_CONSOLE_HOST`：默认 127.0.0.1；对外监听必须配置访问密钥。
- `TEAM_CONSOLE_API_KEY`：API 访问密钥，进入界面时先在独立登录页输入并验证，通过后才加载管理菜单、账号和任务。所有 API（包含复用的母号接口）都受保护；未配置密钥时，登录验证接口拒绝登录。
- `TEAM_CONSOLE_DATA_DIR`：留空默认使用本目录 `data/store`。相对路径以 `team-console` 为基准；不自动迁移任何旧数据，也不能在已运行的进程中热切换目录。
- `TEAM_CONSOLE_AUTH_WORKERS`：普通 / Team 授权共享的实际执行槽位，默认 100，可设为 1–100。启动时固定，调整需要重启新后台；不沿用旧系统的 50 路限制。

前端开发：在 `frontend` 执行 `npm run dev`，默认 3050，API 转发至 5050。

登录密钥仅保存到当前标签页的 `sessionStorage`；刷新页面先重新验证，再显示后台。右上角“退出登录”会清除密钥并返回登录页；服务端密钥变更导致本系统鉴权失败时，也会退回登录页。上游母号自己的 401 不会退出管理台登录。密钥不会硬编码到前端源码或构建文件。

## Docker 独立部署

部署目录结构（与旧后台完全分开）：

```text
/opt/team-console/
  compose.yaml          # 从 team-console/deploy/compose.yaml 复制
  source/               # 主项目业务代码 + team-console；不包含历史数据和 env
  business.env          # 现有代理/授权等业务配置的独立副本，只读挂载
  .console.env          # TEAM_CONSOLE_API_KEY，只读挂载；不要提交 Git
  data/                 # 首次为空，重建容器仍保留新数据
```

`data` 目录和两份 env 必须事先创建，属主设为 `10001:10001`，权限分别为 `700` / `600`。访问密钥可沿用旧后台授权码，但不要放进镜像、命令行参数或构建日志。容器启动时必须有非空访问密钥，否则拒绝对外服务。

```sh
cd /opt/team-console
docker compose build
docker compose up -d
docker compose ps
docker compose logs --tail=100 web
```

默认发布 5050 端口。镜像通过锁文件构建 React 前端，使用单进程 Waitress（16 个 HTTP 线程）而非 Flask 开发服务器；授权使用独立的 100 路线程池，与 HTTP 线程数无关。普通 / Team 授权共享容量，不按每批串行等待；空出的线程立即领取下一个任务。不要扩成多个 WSGI 进程/副本共享此数据目录。

Compose 为新容器配置 4 CPU、4 GiB 内存、5 GiB 内存加交换空间总上限、2048 进程/线程上限；不会修改旧容器。任务中的 Node 子进程同样计入容器资源限制。100 是并行任务上限，不代表远端响应速度或成功率保证。

镜像构建上下文采用白名单，不包含 `.env`、账号、Token、Cookie、历史日志和旧索引。运行时非 root、只读根文件系统，仅 `/data` 和 `/tmp` 可写；含带鉴权的健康检查、资源上限和滚动容器日志。Docker 不会安装或启动浏览器。

更新时只替换 `source` 并重新构建启动；不要覆盖 `data` 或运行清空目录的命令。回滚可以通过 `TEAM_CONSOLE_IMAGE` 指向上一个已构建镜像，使用 `docker compose up -d --no-build`；业务数据仍保留。

## 本轮稳定性 / 性能改进

- 正确挂载 Ant Design App Provider，业务提示与弹窗可获取上下文。
- 页面拆分并按需加载；列表请求可取消，旧请求不覆盖新筛选 / 母号 / 工作区的数据。
- 成员一次读取本地缓存筛选结果，通过虚拟滚动列表展示；官网成员同步仍按每页 100 人。支持标准 / Codex / 基础席位统计、Hold 独立列表、单个及批量切换 / 移除。切换工作区或筛选会清空选择，移除 / 切席需确认目标。
- 成员额度读取 `local_account`，账号额度展示实际窗口剩余比例。
- 授权进度轮询与弹窗独立；切换菜单后仍能查看进行中的授权。
- Team 授权失败或返回 Free 等非 Team 套餐时，最多自动重试 6 次（首次加重试共 7 次）；普通授权重试策略不变，成功或手动停止后不继续重试。
- 账号 / 任务页显示执行池的实际运行数、排队数；排队中的任务不算已运行。`GET /api/jobs` 的 `runtime` 返回这些无凭据计数，不扫描账号 JSON。独立服务不在每个任务启动时并发 reload 全部配置，避免覆盖代理设置或让线程池退回 50 路。
- 批次管理只查询账号导入批次，内部 OAuth 执行批次不混入列表。
- 账号支持按保存的授权套餐精确筛选 `free` / `self_serve_business_prolite`，可与批次 ID 同时筛选；未授权或套餐未知不归入 Free。查询使用 SQLite 索引，不逐条读取凭证。批次页的“查看账号”会自动带入批次筛选。
- 选中账号后，“更多 → 导出 2FA 三段式 TXT”下载 `邮箱----ChatGPT密码----Base32密钥`，一次读取所选凭据，原样保留密码中的空格和分隔符，不误用邮箱密码。已导入但尚未验证的密钥可备份并单独提示；缺失/无效/正在绑定的记录报告失败。只有显式、鉴权的导出请求返回明文，列表和 SQLite 不存入凭据，不更改 2FA 或 Codex 导出状态。
- 入队返回真实数量，零入队不再显示成功；导入成功但授权失败会分开提示；导出保留失败明细，不再把全失败变成空文件下载。
- 不自动重试远端写操作。界面刷新成员读取的是本地缓存，远端同步需要用户显式提交任务。

### 席位控制与网络代理

- 母号成员页提供席位用量 / 可用 / 已购 / Hold 概览；Hold 是单独的保留记录，当前仅展示，不发送成员切换或移除操作。
- 只有工作区明确开放 `usage_based` 时，才能邀请或切换到 Codex 席位。
- 账号批量栏和批次行支持选择母号、工作区，按保存的授权成员 ID 预览并提交切席 / 移出；无邮箱也不依赖邮箱匹配。实际执行复用旧服务的身份检查、限速和“不自动回查”规则。
- 左侧「网络代理」可查看已有代理数量及脱敏示例，显式替换或清空 SOCKS / HTTP 代理池，并设置额度查询路由及专用代理。不会将已有密码回填至前端。
- 未修改时沿用 `business.env`；修改后将独立覆盖配置写入 `data/network-settings.json`（0600 权限）。新建会话即时生效，重建容器仍保留；已有会话保留原代理。不改旧系统配置或只读挂载的 env。

### 索引行为

列表和统计请求只查 SQLite；后台线程默认每 2 秒检查源文件签名。主 JSON 未变、仅 journal 变更时不重新解析主文件。索引仅更新变化的行，账号变化后的批次人数由 SQL 聚合，无需重写全部批次。

首次启动索引未就绪时显示提示；后续继续提供上次完整快照。源文件损坏、读取途中被替换或 journal 不匹配时不会发布半份数据，后台自动重新读取。仍需扫描已变化的主文件；旧服务自身的业务 JSON 写入成本不在本轮消除范围内。

`data/store/read-model.sqlite3` 是可重建的派生缓存，不是凭据主库。账号及批次使用字段白名单；读索引不存储原始 `flow_snapshot`、密码、TOTP、AT、RT 或 Cookie。新导入的凭据由同一独立目录内的业务存储管理，整个数据目录默认被 Git 忽略。

### API 变化

`POST /api/accounts/export-sub2api` 返回 JSON 报告（`data` 是供下载的 Sub2API 内容，另有 `failed` / `warnings` / 数量），全失败为 HTTP 422。授权 / 额度查询全部未入队为 HTTP 409，部分成功保留完整计数和明细。前端与后端需同时更新，然后手动重启新后台、刷新界面。

## 离线验证

在主项目根目录：

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$PWD/team-console" .venv/bin/python -m unittest discover -s team-console/tests -v
```

测试仅使用临时 JSON / SQLite 和模拟业务服务；包括真实旧母号存储的临时实例，验证启动新后台不改变已有 running 任务。不会接触真实账号、调用外部授权或启动应用服务。前端只执行 TypeScript / Vite 静态构建，不执行浏览器或 UI 测试。

并发回归通过真实 API、持久化编排器和授权线程池提交 120 个临时账号（两种授权各 60 个），只替换最外层 OAuth 网络传输：断言同时运行 100、排队 20；只释放其中 1 个就启动第 101 个，而不等待整批结束。同时验证配置 reload 不重建池，取消 / 异常不泄漏运行计数。该测试证明队列与执行槽位，不代替真实上游网络压测。
